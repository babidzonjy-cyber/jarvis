# Jarvis — Development Plan

> Цель: сделать личного локального голосового ассистента для macOS, который умеет понимать голосовые команды, работать с приложениями и постепенно управлять компьютером.
>
> Принцип проекта: **не делать огромную систему сразу**. Каждая новая возможность должна быть маленькой, понятной и рабочей. Код пишется в первую очередь самостоятельно; готовые библиотеки используются только там, где они решают низкоуровневую задачу и не скрывают основную архитектуру.

# 1. Computer Control — первый главный этап

Цель: дать Jarvis возможность выполнять простые действия на экране.

### 1.1 Базовые действия

- [ ] Сделать `screenshot()`
- [ ] Сделать `click(x, y)`
- [ ] Сделать `type(text)`
- [ ] Сделать `press(key)`
- [ ] Сделать `scroll(...)`

### 1.2 Интеграция с tool calling

- [ ] Добавить один понятный `computer` tool
- [ ] Передавать ему только разрешённые действия
- [ ] Не давать LLM выполнять произвольные shell-команды
- [ ] Проверять аргументы инструментов в Go

### 1.3 Первый реальный сценарий

- [ ] Открыть Яндекс Музыку
- [ ] Получить screenshot
- [ ] Найти нужный элемент на экране
- [ ] Кликнуть по нему
- [ ] Проверить результат новым screenshot

**Важно:** сначала всё можно делать вручную/с фиксированными координатами. Автоматический поиск элементов добавлять только после того, как базовое управление работает.

# 2. Vision / поиск элементов на экране

Цель: Jarvis должен понимать, где находится нужная кнопка или элемент интерфейса.

- [ ] Передавать screenshot vision-модели

- [ ] Проверять корректность координат
- [ ] Выполнять click

### Первый сценарий

> «Открой Яндекс Музыку и включи мои любимые треки»

Примерный цикл:

```text
open_app
    ↓
screenshot
    ↓
найти «Мне нравится»
    ↓
click
    ↓
screenshot
    ↓
найти Play
    ↓
click
    ↓
проверить результат
```

Не делать пока универсальный planner. Нужен один работающий сценарий.

# 3. Chill Mode

Цель: Jarvis как обычный компьютерный помощник.

- [x] Открытие приложений
- [ ] Управление музыкой
- [ ] Play / pause
- [ ] Следующий / предыдущий трек
- [ ] Открытие нужного плейлиста
- [ ] YouTube search
- [ ] Простые действия с приложениями через `computer`

### Принцип

LLM не получает прямой доступ к компьютеру.

```text

выбирает tool
 ↓

 ↓
разрешённое действие
 ↓
macOS
```

- [ ] Смотреть вывод терминала

- [ ] Объяснять ошибку

### Позже

# 7. Безопасность и архитектура

Не усложнять архитектуру раньше времени.

### Правила

- [ ] LLM не получает произвольный shell-доступ
- [ ] Каждый tool имеет понятную схему аргументов
- [ ] Опасные действия требуют подтверждения
- [ ] Tools находятся отдельно от LLM-логики
- [ ] `tools → llm` зависимость не допускается, чтобы не получить import cycle
- [ ] Общая логика не дублируется между tools
- [ ] Ошибки возвращаются в LLM как результаты tool calls
- [ ] Сложные механизмы добавлять только после появления реальной необходимости

# 11. Что НЕ делать сейчас

Чтобы проект не превратился в систему, в которой сам разработчик перестаёт понимать код:

- [ ] Не делать полноценный autonomous agent
- [ ] Не делать сложную multi-agent систему
- [ ] Не добавлять десятки tools одновременно
- [ ] Не переписывать архитектуру ради каждой новой функции
- [ ] Не добавлять абстракции «на будущее», пока нет потребности
- [ ] Не подключать большую библиотеку, если небольшую часть можно понятно написать самому
- [ ] Не делать Windows-версию одновременно с macOS

# 12. Приоритеты

Работать строго сверху вниз:

```text
1. Computer control
       ↓
2. Screenshot + click
       ↓
3. Vision / поиск элементов
       ↓
4. Яндекс Музыка как первый полноценный сценарий
       ↓
5. Chill Mode
       ↓
6. Work Mode
       ↓
7. Global Assistant
       ↓
8. Windows
```

Если какой-то этап начинает становиться слишком сложным — остановиться, упростить его и сделать рабочую маленькую версию.

# Главная цель проекта

Jarvis не обязан быть идеальным продуктом.

Главная цель — показать инженерный рост:

- понимать код проекта;
- самостоятельно разбираться с неизвестными технологиями;
- строить понятную архитектуру;
- работать с Go, concurrency и tool calling;
- взаимодействовать с ОС;
- исследовать новые технологии и превращать их в работающие функции;
- уметь объяснить, **почему** каждое решение было принято.

**Лучше 5 хорошо понятных функций, написанных самостоятельно, чем 50 функций, которые работают только благодаря чужим абстракциям.**
